## 二、核心证据：课题 08 传感器数据 ↔ 视频核对报告

[`第一阶段/课题08核对报告.html`](第一阶段/课题08核对报告.html)（可直接双击用浏览器打开）
5 组实验 · phyphox「Acceleration (without g)」· iPhone17,2 · 2026-11-16 · **只读核对，未改动原始文件**。

**总判定**：配对正确、数据本身可信，但「快跑」一组基本没录到有效动作。

核对方法（报告中写明，可复现）：解析 MP4 box 取时长/帧率/编码；用 ffmpeg 均匀抽 6 帧拼联系表；统计 CSV 的采样间隔、幅值分布、逐秒 RMS 与自相关步频；交叉比对 `meta/time.csv` 事件、`meta/device.csv` 与画面状态栏时刻。

**通过的校验**
- `|a| = √(x²+y²+z²)` 五份 CSV 逐行误差为 0；采样间隔中位数 0.0100 s（≈100 Hz），无丢帧、无时间倒序、无大段缺失。
- CSV 末时刻与 `time.csv` 最后一次 PAUSE 的实验时间差 +0.004~+0.023 s（一个采样周期内），导出完整。
- 五份 CSV 之间整行重复数为 0（不存在复制粘贴或放错文件）；`device.csv` 五份 MD5 完全相同。
- 视频均为 592×1280 / 30 fps / HEVC + AAC，同一套录屏导出流程。

**查出的问题（这才是这份报告最值钱的部分）**
1. 快跑组仅 3.88 s，1.66 s 处 PAUSE 后墙钟隔 25.13 s 才 START，真正的跑步极可能发生在暂停期间；逐秒强度单调衰减、视频后 11 秒定格 → **判定无效，安排重采**。
2. 爬楼梯（慢）16 s 后归于平静，有效动作段约 0–15 s，按整段求均值会低估强度 → 分析时裁掉尾部。
3. 慢走视频第 2 帧起 Actions 菜单遮挡上半部曲线，无法目视核对 x/y 曲线。
4. 录屏与采集独立起停（时长差 −4.42~+11.89 s），不能逐秒对齐；建议以后首尾各做一次敲击/拍手留同步尖峰。
5. **不要用文件时间戳对齐**：MP4 的 `creation_time` 是导出/封装时刻，文件修改时间是拷贝时刻，真实采集时刻只认 `time.csv` 与画面状态栏。

后续动作已落到代码和文档里：`analyze_gait.py` 默认排除快跑组、按报告建议裁尾，并在终端打印依据；`01_Stage1_Field_Measurement/课题08/README.md` 逐组列出核对数字。
