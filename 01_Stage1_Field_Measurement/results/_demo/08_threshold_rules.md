# 课题 08 · 步态阈值规则与验证

> 由 `analyze_gait.py` 生成。当前为**合成演示数据（不得写进结论）**。

- 加速度单位：`m/s^2`（Phyphox「Acceleration (without g)」导出的线性加速度）
- 数据源：`results/_demo/`
- **4 类全部纳入**：5 份 CSV 有效时长均 ≥12 s（快跑已 11-19 重采达标），无需再排除任何组。
- 滑窗 3 s，活动段裁剪保留峰值 25% 以上的窗口

## 特征定义

| 特征 | 物理含义 |
|---|---|
| `svm_mean` | 合加速度均值，区分静止 / 慢走 / 快跑（量级指标） |
| `svm_std` | 合加速度波动强度 |
| `az_range` | 垂直轴 95–5 分位幅度 |
| `dominant_hz` | 合加速度主频 |
| `zcr` / `centroid` | 过零率 / 频谱质心 |
| `cadence` | 步频：由垂直轴冲击峰值计数得到的每秒落地次数 |
| `cad_cv` | 步频规整度：相邻步间隔的变异系数 |
| `align` | 步频峰对齐度：步频带峰值占全带峰值的比例 |
| `ratio` | **1×/2× 步频能量比**：步频主峰带 ÷ 二次谐波带能量 |

## 可解释规则

```python
if svm_mean < 1.209:            静止     # 合加速度几乎为零，手机未被携带运动
elif svm_mean >= 1.773:           快跑     # 冲击量级远高于慢走与爬楼
elif ratio < 11.446:                上下楼梯 # 垂向力集中在 1× 步频（单脚支撑）
else:                                        平地慢走 # 双脚交替，能量落在 2× 步频
```

阈值由**训练窗口自动标定**（取两类均值中点）：`svm_static=1.209`、`svm_run=1.773`、`ratio=11.446`；测试窗口完全不参与标定。

### 为什么用 `ratio` 而不是垂直幅度分楼梯

早期版本用 `az_range`（垂直幅度）区分上下楼梯与平地慢走，实测把**大量平地慢走窗口误判成楼梯**：
水平位移幅度与竖直位移幅度在手机手持条件下几乎完全重叠（平地 6.4–12.6 g vs 楼梯 4.4–22.0 g），
单靠幅度无法分开。改用 `ratio` 的物理依据是：

- **平地慢走**：双脚交替支撑，垂向冲击力主要出现在 **2× 步频** → 1× 带能量占比低 → `ratio` 大；
- **上下楼梯**：每级台阶需单脚蹬伸、以单脚支撑为主，垂向力集中在 **1× 步频** → `ratio` 小。

实测平地慢走 `ratio` 均值 2.18、上下楼梯 1.65，间隔明显；`cad_cv`（步频规整度）方向一致，
平地 0.36、楼梯 0.64，可作为面试时的交叉验证。

## 交叉验证结果

- 总窗口 16 个，划分为 4 类
- **重复分层 5 折交叉验证（4 个随机种子 × 20 轮 = 64 次评估）：准确率 39.1%**
- 全量数据自评准确率 43.8%（阈值用全量标定，仅作参考，不作为泛化指标）

### 各折错误明细

| 真实 → 预测 | 次数 |
|---|---|
| 静止 → 上下楼梯 | 16 |
| 平地慢走 → 静止 | 16 |
| 上下楼梯 → 平地慢走 | 7 |

剩余混淆集中在「平地慢走 ↔ 上下楼梯」，原因是两者在幅度与步频上都接近，只有节奏规整度与频带能量比能区分；这是当前数据量下的可分性上限。

## 更严格的一层：留一整份源文件

上面的 K 折验证里，同一文件的不同窗口会分别落进训练折与测试折，窗口之间高度相似，因此分数偏乐观。下面把**一整个采集文件**留作测试，训练集完全不含它的任何窗口，模拟「换一个人、换一天重新采集」的情形：

| 留出的源文件 | 命中 | 窗口数 |
|---|---|---|
| `gait_上下楼梯_demo.csv` | 0 | 4 |
| `gait_平地慢走_demo.csv` | 0 | 4 |
| `gait_快跑_demo.csv` | 0 | 4 |
| `gait_静止_demo.csv` | 0 | 4 |

- **留一整份文件的准确率：0.0%**（16 个窗口）

**必须如实说明的两点：**

1. 留出「快跑」文件时正确率为 0——因为快跑目前只有 1 份源文件，训练集中根本不存在快跑这一类，阈值无从标定，该类必然全错。这不是规则写错了，而是**每类只有 1 次采集**的数据量限制。
2. 因此 K 折的 39.1% 应理解为「同一次采集内的窗口级可分性」，不能理解为「换人换天仍能保持的水平」。要真正验证泛化能力，需要每类至少 3 次独立采集。

这两层数字都写在这里，是为了说明结论的**适用边界**，而不是挑一个好看的报。

## 阈值重标定说明

- 三个阈值由脚本从训练窗口自动标定（两类均值中点），换真实数据后自动更新，不用手改代码。
- 若准确率不理想：先看上表哪两类特征范围重叠，考虑延长窗口或更多依赖节奏类稳健特征。
- 手机固定位置（口袋 / 手持 / 臂包）会显著改变幅度类特征，全程保持一致并在 README 写明。
- 步频与节奏类特征比幅度更稳健：不同人、不同鞋、不同手机位置下，节奏变化小于幅度变化。
