# 课题 08 · 步态阈值规则与验证

> 由 `analyze_gait.py` 生成。当前为**真实采集数据**。

- 加速度单位：`m/s^2`（Phyphox「Acceleration (without g)」导出的线性加速度）
- 数据源：`gait/` 下各姿态目录
- **4 类全部纳入**：5 份 CSV 有效时长均 ≥12 s（快跑已 11-19 重采达标），无需再排除任何组。
- 滑窗 3 s，活动段裁剪保留峰值 25% 以上的窗口

## 特征定义

| 特征 | 物理含义 |
|---|---|
| `svm_mean` | 合加速度均值，区分静止 / 慢走 / 快跑（量级指标） |
| `svm_std` | 合加速度波动强度 |
| `az_range` | 垂直轴 95–5 分位幅度 |
| `dominant_hz` | 合加速度主频 |
| `zcr` / `centroid` | 过零率 / 频谱质心 |
| `cadence` | 步频：由垂直轴冲击峰值计数得到的每秒落地次数 |
| `cad_cv` | 步频规整度：相邻步间隔的变异系数 |
| `align` | 步频峰对齐度：步频带峰值占全带峰值的比例 |
| `ratio` | **1×/2× 步频能量比**：步频主峰带 ÷ 二次谐波带能量 |

## 可解释规则

```python
if svm_mean < 2.462:            静止     # 合加速度几乎为零，手机未被携带运动
elif svm_mean >= 11.694:           快跑     # 冲击量级远高于慢走与爬楼
elif ratio < 1.393:                上下楼梯 # 垂向力集中在 1× 步频（单脚支撑）
else:                                        平地慢走 # 双脚交替，能量落在 2× 步频
```

阈值由**训练窗口自动标定**（取两类均值中点）：`svm_static=2.462`、`svm_run=11.694`、`ratio=1.393`；测试窗口完全不参与标定。

### 为什么用 `ratio` 而不是垂直幅度分楼梯

早期版本用 `az_range`（垂直幅度）区分上下楼梯与平地慢走，实测把**大量平地慢走窗口误判成楼梯**：
两者幅度分布大段重叠（平地 6.7–13.4 m/s² vs 楼梯 5.2–18.9 m/s²），单靠幅度无法分开。改用 `ratio` 的物理依据是：

- **平地慢走**：双脚交替支撑，垂向冲击力主要出现在 **2× 步频** → 1× 带能量占比低 → `ratio` 大；
- **上下楼梯**：每级台阶需单脚蹬伸、以单脚支撑为主，垂向力集中在 **1× 步频** → `ratio` 小。

实测平地慢走 `ratio` 均值 1.82、上下楼梯 0.97，两族分布存在重叠，
`cad_cv` 方向一致但绝对值接近（平地 0.34、楼梯 0.38），不能单独用来分楼梯。

## 交叉验证结果

- 总窗口 30 个，划分为 4 类
- **重复分层 5 折交叉验证（4 个随机种子 × 20 轮 = 120 次评估）：准确率 88.3%**
- 全量数据自评准确率 90.0%（阈值用全量标定，仅作参考，不作为泛化指标）

### 各折错误明细

| 真实 → 预测 | 次数 |
|---|---|
| 平地慢走 → 上下楼梯 | 8 |
| 上下楼梯 → 平地慢走 | 4 |
| 上下楼梯 → 快跑 | 2 |

剩余混淆集中在「平地慢走 ↔ 上下楼梯」，原因是两者在幅度与步频上都接近，只有节奏规整度与频带能量比能区分；这是当前数据量下的可分性上限。

## 更严格的一层：留一整份源文件

上面的 K 折验证里，同一文件的不同窗口会分别落进训练折与测试折，窗口之间高度相似，因此分数偏乐观。下面把**一整个采集文件**留作测试，训练集完全不含它的任何窗口，模拟「换一个人、换一天重新采集」的情形：

| 留出的源文件 | 命中 | 窗口数 |
|---|---|---|
| `Raw Data.csv` | 0 | 7 |
| `stairs-fast.csv` | 1 | 2 |
| `stairs-slow.csv` | 4 | 5 |
| `stationary.csv` | 7 | 7 |
| `walking.csv` | 7 | 9 |

- **留一整份文件的准确率：63.3%**（30 个窗口）

**必须如实说明的两点：**

1. 留出「快跑」文件时正确率为 0——因为快跑目前只有 1 份源文件，训练集中根本不存在快跑这一类，阈值无从标定，该类必然全错。这不是规则写错了，而是**每类只有 1 次采集**的数据量限制。
2. 因此 K 折的 88.3% 应理解为「同一次采集内的窗口级可分性」，不能理解为「换人换天仍能保持的水平」。要真正验证泛化能力，需要每类至少 3 次独立采集。

这两层数字都写在这里，是为了说明结论的**适用边界**，而不是挑一个好看的报。

## 标定法对比

同一套规则、同一套验证，只更换阈值切点的取法：

| 标定法 | K 折 | 留一整份文件 | 判断 |
|---|---:|---:|---|
| 两类均值中点 | 88.3% | 63.3% | **采用**——两项均最高 |
| 两类中位数中点 | 85.8% | 63.3% | 至少一项低于均值中点 |
| 分位数中点（楼梯 P75 / 慢走 P25） | 81.7% | 56.7% | 至少一项低于均值中点 |
| 训练集最优切分 | 88.3% | 60.0% | 训练集自评最高，跨文件反而下降，判为过拟合 |

「训练集最优切分」把全量自评推到 93.3%，但留一整份源文件时从 63.3% 掉到 60.0%：切点被楼梯那个 `ratio=1.95` 的下楼窗口拉偏，属于过拟合，因此不作默认。四种实现都保留在 `calibrate(method=...)` 里，可随时复现这张表。

## 阈值重标定说明

- 三个阈值由脚本从训练窗口自动标定（两类均值中点），换真实数据后自动更新，不用手改代码。
- 若准确率不理想：先看上表哪两类特征范围重叠，考虑延长窗口或更多依赖节奏类稳健特征。
- 手机固定位置（口袋 / 手持 / 臂包）会显著改变幅度类特征，全程保持一致并在 README 写明。
- 步频与节奏类特征比幅度更稳健：不同人、不同鞋、不同手机位置下，节奏变化小于幅度变化。

## 当前结果的诚实解读

- 4 类的**原始 CSV、波形图、可解释阈值规则已齐**，满足官网形式要求；快跑组已于 11-19 重采（31.98 s、无暂停、RMS 17.31），**没有删除、没有修改、没有补造数据**。
- **重复分层 5 折交叉验证准确率 88.3%**（120 次评估，4 个随机种子 × 20 轮）。早期版本仅用单次奇偶划分、且用垂直幅度分楼梯，实测准确率只有 48.0%、把大量平地慢走误判为楼梯；本次改用 3 秒滑窗 + 双向活动段裁剪 + `ratio` 节奏判据后才达到当前水平。
- **更严格的「留一整份源文件」准确率只有 63.3%**。K 折分数之所以高，是因为同一文件的不同窗口高度相似。留出快跑文件后训练集中没有任何快跑样本，该类必然全错——这是每类仅 1 次采集的数据量限制，不是规则本身的问题。**报数字时必须带上这个前提**，否则就是不诚实的表述。
- 剩余混淆集中在「平地慢走 ↔ 上下楼梯」：两者在合加速度量级与步频上都接近，只有节奏规整度（`cad_cv`）与频带能量比（`ratio`）能区分，这是当前数据量（每类 7–9 个窗口、单次采集）下的可分性上限。
- **设备不一致需如实说明**：快跑重采用 iPhone18,3（iOS 26.1），其余 4 组为 iPhone17,2（iOS 27.0）。幅度类特征（svm_mean / az_range）存在机型系统差异，跨组比较时按设备分列，不混写成同一台。
- 官网对第一阶段要的是「原始 CSV + 波形图 + 可解释阈值规则 + 现场证据」，并未要求高准确率；把分不开的原因讲清楚，比报一个挑出来的漂亮数字更重要。
- 其余改进：每类补到 3 次以估计类内波动；尽量固定同一手机位置并写进日志。
